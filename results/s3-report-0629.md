# LLM 推理服务部署 — 阶段三：量化对比实验报告

## 一、实验概述

本阶段对 Qwen2.5-7B-Instruct 进行三种精度的部署对比，验证"量化不总是更快"的工程结论，并给出场景化选型建议。

| 精度 | 权重大小 | 模型加载显存 | KV Cache 预留 | 理论最大并发 |
|------|---------|-------------|--------------|-------------|
| FP16 | 14.2 GB | 14.25 GB | 5.38 GB | 24.6x |
| **AWQ-INT4** | ~4.1 GB | **5.20 GB** | **14.32 GB** | **65.5x** |
| **FP8** | ~8.1 GB | **8.14 GB** | **11.30 GB** | **51.7x** |

> 注：AWQ 和 FP8 均为 weight-only 量化之外的方案——AWQ 是 INT4 weight-only（计算前反量化），FP8 是在线 weight-activation 量化（4090 Ada 架构原生支持）。

## 三、核心洞察

### 3.1 结论一：FP8 是"最稳的全优生"，不是 AWQ

任务书预判"量化未必更快"，实测结果更具体：**FP8 在所有并发档位下都是吞吐最高、延迟控制最好的方案。**

- **64 并发吞吐排序**：FP8(3324) > AWQ(2439) > FP16(2098)
- **64 并发延迟排序**：FP8(9.26s) < AWQ(12.73s) < FP16(14.49s)

FP8 在 4090（Ada 架构）上有原生硬件支持，矩阵乘法走 Tensor Core FP8 路径，不需要像 AWQ 那样在计算前用 CUDA Core 做反量化。这使得 FP8 在高并发时**扩展性更好**——AWQ 的吞吐从 1→64 并发仅提升 19 倍，FP8 提升了 36 倍。

### 3.2 结论二：AWQ 的"低延迟优势"只在低并发成立

AWQ 单请求 P50=3.62s，只有 FP16 的 45%，原因是 TPOT 极低（8ms vs 17ms）。INT4 权重让每次 decode step 的显存带宽压力减半，单请求确实快。

**但 AWQ 的扩展性远不如 FP8**：
- TPOT 从 8ms 涨到 25ms（64 并发，涨幅 3.1x）
- FP8 的 TPOT 从 11ms 涨到 18ms（64 并发，涨幅仅 1.6x）

根本原因：AWQ 的 **online dequantization**（计算前把 INT4 反量化为 FP16）在高并发时成为瓶颈——反量化操作占用 CUDA Core，与矩阵乘的 Tensor Core 争抢资源，batch 越大越明显。FP8 则全程走 Tensor Core，没有这一步。

### 3.3 结论三：INT4 的"显存优势"被高估了

AWQ 权重只有 5.2GB，比 FP16 省了 9GB 显存，KV Cache 预留高达 14.32GB。理论上能扛 65 并发，但实际 64 并发时吞吐和延迟都不如 FP8。

**显存不是瓶颈，计算效率才是。** 在 24GB 的 4090 上，即使 FP16 的 KV Cache 只有 5.38GB，也能跑到 64 并发（KV Cache usage 峰值约 38%，日志数据）。AWQ 多出来的 KV Cache 空间并不能转化为实际吞吐优势，因为瓶颈在计算端（dequantization + 矩阵乘）而非显存容量。

### 3.4 场景化选型结论

| 场景 | 推荐方案 | 理由 |
|------|---------|------|
| **低并发、延迟敏感**（如对话式应用，并发<8） | AWQ-INT4 | 单请求延迟最低（3.6s），体验最好 |
| **高并发、吞吐优先**（如批量推理、API 服务） | **FP8** | 64 并发吞吐比 AWQ 高 36%，延迟低 27% |
| **显存极度受限**（如边缘设备、多模型共存） | AWQ-INT4 | 权重只有 FP16 的 36%，省出空间给 KV Cache |
| **通用生产环境** | **FP8** | 无需权衡——延迟、吞吐、扩展性全面领先 |

## 四、面试话术要点

**Q："量化一定能让推理更快吗？"**
> 不一定，取决于量化类型和并发量。我的实测显示，AWQ-INT4 单请求延迟只有 FP16 的 45%，但 64 并发时 FP8 的吞吐反而比 AWQ 高 36%。
>
> 原因是 AWQ 属于 weight-only INT4 量化，计算前必须把权重反量化回 FP16，这个 online dequantization 用 CUDA Core 处理，高并发时与矩阵乘争抢资源，扩展性差。FP8 在 4090 上有原生 Tensor Core 支持，全程不需要反量化，所以高并发下扩展性最好。
>
> 结论是：低并发选 AWQ 延迟最低，高并发选 FP8 吞吐最高，显存受限选 AWQ 省空间。

**Q："为什么 AWQ 省了一半显存，吞吐却没翻倍？"**
> 因为瓶颈不在显存容量，而在计算效率。实测中 FP16 的 KV Cache usage 峰值只有 38%，显存根本没用完。AWQ 多出来的 KV Cache 空间无法转化为吞吐，因为每次 decode step 的反量化操作已经卡住了计算流水线。
